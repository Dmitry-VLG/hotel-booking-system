# Автоматические сквозные проверки

Из корня репозитория с JDK 21 и Maven 3.9 выполните:

```powershell
mvn -Pe2e clean verify
```

Maven сначала собирает четыре исполняемых JAR, затем Failsafe запускает SystemFlowIT. Тесты используют настоящие Eureka, Gateway, Booking и Hotel с отдельными H2. Порты выбираются автоматически, ключи и пароли генерируются локально. Пользовательские приложения и данные не используются.

Тестовый HTTP-прокси перед Hotel позволяет потерять ответ после фактического commit и временно отклонить release. Это проверяет реальный read timeout, повтор с тем же reservationId, отсутствие повторного увеличения счётчика и освобождение фоновым восстановителем. В производственном коде средств инъекции сбоев нет.

Сценарии: успешная бронь и повтор, права владельца, 12 конкурентных бронирований одного номера, несуществующий номер, 404/405/415 через Gateway, отказ Hotel, потеря ответа и автоматическая компенсация, распределение девяти бронирований по трём номерам, реальные Eureka/OpenAPI и ограничения доступа. Состояния хранилищ читаются через API сервисов.

Отчёты: target/failsafe-reports. Логи приложений: target/e2e. При завершении останавливаются все созданные набором JVM и удаляются временные PEM-файлы. Перед каждым сценарием проверяется восстановление CircuitBreaker после искусственных отказов; каждый сценарий создаёт собственные отель и номера.

Это проверка конечного набора сценариев, а не доказательство поведения при любой нагрузке или всех возможных сетевых сбоях.
