# Подбор кандидатов при конкуренции

Проблема: один снимок первых 100 свободных номеров может устареть до попытки hold. Возврат 409 после исчерпания этого списка не доказывает отсутствие других свободных номеров.

Решение: Booking запоминает номера, получившие подтверждённый отказ hold, и запрашивает у Hotel следующую партию через внутренний POST /internal/rooms/recommend. В запрос передаётся список исключений. Hotel заново фильтрует доступность и занятость, исключает проверенные номера и сохраняет сортировку timesBooked, id. Смещение страниц не используется, поэтому исчезновение занятых номеров из выдачи не приводит к пропуску следующей страницы.

Неизвестный исход hold не позволяет перейти к другому номеру: сначала выполняется безопасная компенсация текущего резерва. Подбор ограничен общим дедлайном операции. Для защиты памяти и размера внутреннего запроса установлен бюджет 10000 исключений. Исчерпание бюджета возвращает 503 SELECTION_BUDGET_EXCEEDED, а не ложный 409 NO_AVAILABLE_ROOM; 409 используется после пустой актуальной выдачи. Повтор после временной ошибки — новое намерение с новым Idempotency-Key.

Компонентные тесты проверяют 100 конфликтов и успешный выбор 101-го кандидата, обновление выдачи Hotel после конкурентной занятости и распределение серии подтверждений по счётчику.
